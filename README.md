# 📈 家庭基金账目管理系统 (Family Fund Management System)

一个专门为家庭/小型合伙基金设计的 **高精度、可追溯、全自适应** 的资产账目与份额净值管理系统。基于 **事件溯源 (Event Sourcing)** 架构开发，保证账目的历史可追溯性与绝对准确度。

---

## ✨ 核心功能亮点

* **📅 事件溯源重放计算**：采用先进的事件溯源架构，所有的入金、出金、份额转让与估值更新均被记录为独立事件，系统通过历史流重放计算成员的最精细化资产净值与份额。
* **💹 份额净值实时核算**：实时追踪每一笔交易发生瞬间的基金总资产（Total NAV）、总份额（Total Shares）与单位净值（NAV per Share）。
* **🔄 人民币/美元双维度双币核算**：
  * 支持输入实际的人民币流水并记录美元出资；
  * 内置自适应汇率同步接口，启动时静默同步全球最新离岸人民币（CNH）汇率。
* **📉 标普500/纳指100指数对比**：静默后台从 Yahoo Finance 同步对标美股大盘指数（SPX、NDX），并在前端生成归一化走势对比图表，直观了解投资表现是否跑赢大盘。
* **🔁 成员内部份额划转**：支持家庭成员之间的高精度份额转让与资产转拨，自动折算对应时间节点的净值与汇率。
* **🛡️ 极致的安全机制与自动备份**：
  * **完整快照保护**：账目、配置或结算发生持久化修改前，系统都会在 `backups/` 生成可直接导入的完整 ZIP 快照，包含 `db.json`、`config.json` 与 `settlements.json`，滚动留存最新 15 份。
  * **结算账本防丢**：系统初始化结算账本后，如果 `settlements.json` 意外丢失会拒绝继续运行并提示恢复，不会静默创建空账本；三文件恢复通过持久化事务日志保证进程崩溃或断电后自动回到完整的旧版本。
  * **删除安全保护**：已产生财务流水（如出入金）的成员，系统将绝对禁止直接删除其账号，防止破坏历史财务计算链条。
  * **一键导出导入**：支持将三份核心数据打包为 ZIP 完整快照，并可在任意新设备上一键校验恢复。

## 🚀 快速启动指南

为了方便家庭成员使用，项目已内置 **一键免命令启动器**：

### 💻 方案 A：双击一键启动（推荐）

* **Windows 用户**：
  直接双击项目根目录下的 **`start.bat`** 脚本即可。
* **macOS 用户**：
  首次使用时需要授权，请打开终端，输入 `chmod +x `（+x 后面有一个空格），把 **`start.command`** 文件拖入终端回车。之后只需双击 `start.command` 即可运行。

> **启动器会自动为您完成以下配置：**
> 1. 自动检查是否安装了 Node.js（若无则提示下载）。
> 2. 自动检查并安装依赖环境。
> 3. 自动在浏览器中为您打开系统主界面：👉 **[http://localhost:3000](http://localhost:3000)**

---

### 🛠️ 方案 B：手动命令启动

如果您习惯使用命令行，也可以通过以下步骤手动启动：

1. **安装环境**：请确保电脑已安装 [Node.js](https://nodejs.org/)。
2. **安装依赖**（仅需首次执行）：
   ```bash
   npm install
   ```
3. **启动服务器**：
   ```bash
   npm start
   ```
4. **浏览器访问**：打开浏览器，访问 `http://localhost:3000`。

## ⚙️ 进阶配置与常见问题 (FAQ)

### 业绩结算

“业绩结算”页签采用固定的 `6% / 25%` 规则（零固定管理费）：每笔 LP 入金或受让资金都是独立批次，首个计费周期从实际入账日起算，此后每次正式结算都会结束本期并从结算日重新计算下一期天数。批次门槛为“高水位基准 × (1 + 6%)^(本期实际天数 ÷ 365)”；只对超过自身门槛的部分提取 25% 业绩报酬，不同批次之间不做盈亏对冲。时间周期会重启，但每份份额的高水位 NAV 只升不降：结算后的新高水位 NAV 取“原高水位 NAV”与“结算日 NAV”的较高者。业绩报酬只是按结算日 NAV 将相应份额从 LP 划给 GP，不会改变基金 NAV；系统再用 LP 剩余份额乘以高水位 NAV，得到下一期该批次的高水位基准金额。某期低于高水位时不收费，也不会降低以后修复亏损所需跨越的水位；某期虽未达到 6% 门槛但 NAV 创出新高时，该新高会成为下一期水位。高水位 NAV 一致的批次可以合并，否则继续分批保留。LP 部分出金或内部转让时，录入金额视为 LP 实收净额，处置比例等于“实收净额 ÷ 全部批次扣费后可退出净值”；所有存量批次按该比例同步结晶，每批次的 LP 实收份额与 GP 报酬份额之和严格等于该批次总扣减份额。成员本人兼任 GP 时，超过 LP 扣费后可退出净值的实收金额会继续从其已归属 GP 报酬中支付；全额退出时两类份额一并结清。

所有成员均为LP，其中一人可额外兼任全系统唯一的GP；系统会将该成员的LP投资份额与GP业绩报酬份额分账核算。成员卡片可展开查看每笔LP批次的本期起始日、高水位基准、当前价值和截至当前的年化 6% 门槛。

操作时选择结算日期并点击“预览结算”。系统使用结算日当天或此前最近一次基金估值，并在预览中标明估值来源日期。确认后系统保存逐LP计算快照和结算算法版本，并锁定该日期及以前的账目；结算记录不能直接修改或删除。历史回放始终调用该记录对应的冻结算法，并用锁定快照校验结果，后续算法升级不会改写已经确认的成员余额。

账务数据采用双轨存储：`data/db.json`只保存出入金、估值和普通转让，`data/settlements.json`独立保存业绩结算与冲销审计记录。点击“撤销最近一次结算”不会删除原结算，而是追加冲销记录；系统重新重放两套账本、还原LP/GP份额和门槛，并解除相应锁账。只能按顺序撤销最新的有效结算。

### 1. 端口冲突/自定义运行端口
系统默认运行在 `3000` 端口。如果您的电脑上该端口已被其他程序占用，或者您希望自定义端口，可以通过以下方式指定：
* **命令行/终端启动**：
  * **macOS/Linux**：
    ```bash
    PORT=3001 npm start
    ```
  * **Windows (PowerShell)**：
    ```powershell
    $env:PORT=3001; npm start
    ```
  * **Windows (CMD)**：
    ```cmd
    set PORT=3001 && npm start
    ```
* **一键启动器修改**：您也可以直接右键编辑 `start.bat` 或 `start.command`，在 `npm start` 前加入对应的端口声明。

### 2. 美股大盘指数（SP500/纳指100）对比图未显示？
* **原因**：系统内置后台静默同步机制，请求 Yahoo Finance 获取指数收盘价。在部分国内网络环境下，可能会因为网络限制导致 API 请求超时或失败。
* **影响**：此问题**完全不会**影响成员资金录入、出入金以及高精度的份额计算，仅影响大盘对比走势图的渲染。
* **解决建议**：可开启网络代理，或在连网状态下重新启动服务，系统成功拉取并缓存数据后，后续即使离线也能正常展示历史图表。

### 3. 数据备份与恢复如何操作？
* **自动备份**：账目、标的配置或业绩结算发生持久化修改前，系统都会在 `backups/` 下生成 `snapshot_backup_*.zip`，包含三份核心数据且可直接通过导入页面恢复；自动滚动留存最新 15 份。
* **手动备份/迁移**：
  * 可以在系统主页点击 **“导出数据”** 按钮，一键下载包含账目、独立结算账本和标的配置的 ZIP 完整备份。
  * 在新设备或重设系统时，点击 **“导入数据”** 并选择该 ZIP。系统会先校验历史结算版本和锁定快照，再将三份数据原子恢复并重算所有历史份额净值；校验或写入失败时不会留下半恢复状态。
  * 您也可以停止服务后，手动备份或拷贝项目根目录下的整个 `data/` 文件夹。
